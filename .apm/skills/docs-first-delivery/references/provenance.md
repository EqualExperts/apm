# Provenance and evidence

Authored for this marketplace on 2026-11-12 after reviewing the maintainer's existing docs-first delivery workflow. This is a newly written, portable expression of its staged specification, planning, verification and continuation approach. No client repository files, internal URLs, operational examples, scripts or templates were copied into this package.

Adaptation decisions: preserve the consuming repository's layout, compatibility requirements and approval policy; do not impose mandatory tickets, unconditional PR creation, universal forward-only changes, engine-based auto-approval, a rules submodule or a blanket prohibition on clean builds. Keep continuation records where the repository permits them. These choices preserve the workflow without exporting project-specific rules.

Experimental. Stewardship: Equal Experts APM maintainers; individual long-term ownership is unassigned. Requires access to the consuming project's authorized source, specifications and existing verification tools. No external service, MCP server, framework or bootstrap script is required. There are no automatic file mutations.

The PR records package validation, content/security scans, catalogue and browser checks, and prompt installation observations. These do not prove behavioural reliability across assistants or successful delivery of a production feature. The linked scenario review records manual instruction checks separately from runtime evidence.

See [review scenarios](review-scenarios.md) for the cases used to inspect the workflow's decision boundaries.
