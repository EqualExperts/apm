# SPDD analysis record

Record the requested outcome, input sources, date and repository revision inspected. Use the project's existing identifiers and artifact location.

## Intent and scope

State the problem, intended users, boundaries and known acceptance expectations. Separate decisions from assumptions and questions.

## Current behaviour and domain

Describe relevant concepts, relationships, interfaces and existing behaviour. Link source files and tests that support observations. Mark areas not inspected.

## Options and recommendation

Compare feasible approaches and relevant trade-offs. State why the recommended direction fits existing constraints, and what would change the decision.

## Risks and open decisions

Capture consequential compatibility, security, integration, data and operational concerns. Identify decisions needed before canvas creation and evidence needed to resolve them.

## Handoff

List affected components, candidate verification boundaries, reusable artifacts and the next authorized stage. This analysis does not establish design approval or implementation completion.
