# SDD: Design

Read the current specification and relevant repository policy. Define interfaces, data shapes, validation, error behaviour, authorization boundaries and integration contracts required by the change. Consider failure, concurrency and migration cases where applicable. Map each design decision to an acceptance criterion and existing component. Identify contradictions and unsupported assumptions; do not mark an unresolved design as approved. Update only the necessary design artifacts, then state readiness and remaining decisions for implementation planning.
