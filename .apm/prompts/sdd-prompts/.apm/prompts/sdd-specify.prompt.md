# SDD: Specify

Use the requested outcome and current project evidence to write a concise specification: users, problem, boundaries, exclusions, constraints, affected components and observable acceptance criteria. Separate current behaviour from proposed behaviour and identify consequential unknowns. Use Mermaid only where a diagram improves understanding. Preserve existing compatibility and security requirements. Resolve decisions that would change scope before dependent design or implementation; honour review gates already established and authorization already given.
