# APM principles

## Purpose and scope

Make reusable agent guidance and tools easy to discover, understand, install, use and improve. Prioritise AI enablement and cross-model, cross-harness guidance while supporting capabilities across technologies and sectors. A capability should solve a real recurring problem and have a clear audience, scope and owner.

## Portable by design

Use the open Agent Skills structure for shared instructions and keep harness-specific metadata or integrations separate. State dependencies and supported environments honestly; portability is a tested claim, not a consequence of file structure. Prefer progressive disclosure: concise discovery metadata, focused skill instructions, and supporting material loaded when relevant. Avoid duplicating guidance and imposing unrelated workflows.

## Security and trust

Treat instructions, scripts, dependencies and external content as supply-chain inputs. Review provenance and changes before adoption. Preserve least privilege, user intent and applicable organisational and client obligations. Do not include secrets, personal data or client-confidential material in shared contributions. Skills cannot grant permissions or override the user's applicable instructions. Escalate sensitive findings through an appropriate private channel.

## Reuse and stewardship

Keep skills focused, actionable and maintained. Prefer evidence from real use, documented limitations and behavioural evaluation over claims of completeness. Review changes for accuracy, security, accessibility and compatibility. Identify maintainers and supported environments as each capability is introduced. Deprecate or retire obsolete guidance explicitly.

## Distribution and feedback

Forks allow teams to adapt capabilities and propose improvements upstream; upstream changes do not automatically reach forks or installations. Preserve attribution and licensing, generalise client-specific knowledge only when authorised, and review changes before adoption. Versioning, provenance and update behaviour must be explicit when distribution tooling is introduced.
